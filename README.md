# Lumo — доступное обучение программированию

Этап 8: подготовка GitHub и размещения сайта/API с внешней PostgreSQL. Платформа содержит уроки, редактор, проверку заданий, необязательные аккаунты и синхронизацию прогресса. Ручные проверки скринридерами остаются открытыми.
Аудитория — начинающие от 14 лет. Рабочее название Lumo можно заменить.

## Запуск

Нужен Node.js 22.12+ (рекомендуется ветка 24) и пакетный менеджер pnpm.
Версии зависимостей зафиксированы в `pnpm-lock.yaml`, pnpm — в `package.json`, версия Node для размещения — в `.node-version`.

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

Команда запускает сайт и API. Откройте адрес, который напечатает Vite, обычно http://127.0.0.1:5173. API работает на http://127.0.0.1:3001; данные сохраняются в `.data/lumo/`.
Остановка сервера — Ctrl+C. Исходные файлы уже созданы, копировать код вручную не нужно.
Не открывайте `index.html` двойным щелчком: React-проекту нужен сервер Vite.

Чтобы открыть локальную версию на телефоне в той же Wi-Fi сети, запустите фронтенд с `pnpm exec vite --host 0.0.0.0` и используйте IPv4-адрес компьютера вместо `127.0.0.1`. Для аккаунтов также запустите API и добавьте адрес сайта, открываемый на телефоне, в разрешённые `APP_ORIGINS`, как описано в [инструкции бэкенда](server/README.md). Компьютер и серверы должны оставаться включёнными. Сайт ещё не опубликован.

Зависимости уже установлены. Если pnpm отсутствует в PATH, сайт и API можно запустить так:

```powershell
node scripts/dev.mjs
```

Для установки pnpm используется `npm install --global pnpm@11.25.0`.

## Размещение

Исходники: [ShiroHatS/Diplom-](https://github.com/ShiroHatS/Diplom-). Конфигурация `render.yaml` готовит один бесплатный Render Web Service для сайта и API; PostgreSQL подключается через секрет `DATABASE_URL` из Neon. Подробные шаги, настройки, ограничения бесплатных планов и проверка после публикации — в [инструкции размещения](docs/deployment.md).

Наличие файлов размещения не означает, что внешний сервер уже запущен. Подтверждённый адрес добавляется в инструкцию только после успешного развёртывания.

## Что работает

Результаты этапа 7, исправления и матрица оставшихся ручных проверок — в [отчёте аудита](docs/accessibility-audit.md). После расширения программы набор содержит 60 браузерных тестов. Проверяются малая высота окна, 200% текста с интервалами, контраст границ, forced colors, зоны нажатия 44 × 44 и сохранение фокуса. Диалоги прокручиваются целиком, включая заголовок и нижние кнопки.

- Русский и английский: переключается весь интерфейс, заголовок вкладки и `html lang`.
- Светлая, тёмная, системная темы. Системная тема реагирует на изменения ОС.
- Сохранение языка и темы локально. При блокировке хранилища сайт продолжает работать, но настройки не сохранятся после закрытия.
- Переходы к разделам, ссылка пропуска навигации, видимый клавиатурный фокус.
- Переключение трёх примеров кода и раскрытие планов направлений.
- Реакции кнопок на наведение и нажатие с учётом `prefers-reduced-motion`.
- Адаптация для смартфона, планшета и компьютера.
- Панель настроек: размер текста 100–150%, три межстрочных интервала, высокая контрастность, OpenDyslexic, отключение анимации, простой язык и режим фокуса.
- Настройки действуют независимо, сохраняются локально и сбрасываются одной кнопкой. Панель открывается с клавиатуры и закрывается клавишей Esc.
- Восемнадцать коротких уроков: по шесть для Python, JavaScript и HTML + CSS, на русском и английском.
- Каждый урок состоит из теории, объяснения термина, примера, практики и автоматической проверки. Можно переключаться между шагами.
- Текущий урок, отмеченные как пройденные уроки и текст практики сохраняются в этом браузере без регистрации. Прогресс показан числом и полосой.
- На шаге «Практика» можно запускать Python и JavaScript, смотреть вывод и переходить к строке ошибки.
- Для уроков HTML и CSS доступен предпросмотр. CSS применяется к небольшой готовой странице с заголовком и абзацем; можно выбрать ширину до 360 px.
- Ctrl+Enter / ⌘+Enter запускает код. Tab выходит из редактора. Кнопка «Вставить отступ» добавляет четыре пробела. Код ограничен 2000 символами, как и сохраняемый черновик.
- На шаге «Проверка» кнопка «Проверить решение» запускает учебные тесты. Критерии показаны текстом с отметками; результат объявляется через область статуса.
- После успешной проверки урок автоматически отмечается пройденным. Подсказки раскрываются по одной; пример ответа доступен отдельно.
- Причина непринятого ответа показывается сразу под результатом проверки. На практике пустой вывод объясняется текстом; кнопка «Перейти к проверке» ведёт к проверке задания.
- Проверку можно остановить. Переход к практике или другому уроку также отменяет её и удаляет среду выполнения.
- Необязательный аккаунт: регистрация, вход, выход и восстановление доступа по личному коду без обязательного email.
- Синхронизация пройденных уроков и черновиков между устройствами; отличающиеся версии одного черновика предлагаются на выбор.
- Гостевой прогресс хранится отдельно. Для переноса в аккаунт нужно выбрать соответствующий флажок.

В разделе уроков появилась кнопка «Аккаунт». Как запустить сервер, где лежит база, как работают вход и конфликты и что потребуется при публикации — в [server/README.md](server/README.md).

## Как проверяются задания

Проверка сравнивает поведение программы и учебную цель, а не полный исходный текст с образцом. Другие имена, кавычки, пробелы, комментарии и эквивалентные CSS-цвета допустимы. Синтаксические ошибки, зависший код и сбой загрузки среды получают разные сообщения. Число попыток и время обдумывания не ограничены.

| Урок | Критерии |
| --- | --- |
| Python / JavaScript: вывод | `print` / `console.log` выводит непустое текстовое значение. Пустая строка и число не выполняют задание про имя. |
| Python / JavaScript: переменная | `name` создаётся на верхнем уровне программы, хранит непустой текст и используется в команде вывода; результат содержит её значение. |
| Python: условие | `points` начинается со значения 7; `if` использует переменную и содержит вывод. Исходный запуск и подстановки 4, 5, 6 проверяют поведение ниже порога, на пороге и выше него. |
| JavaScript: условие | Аналогично для `age = 14`, с пробными значениями 13, 14, 15. |
| HTML | Есть видимый заголовок `h1` с непустым текстом. |
| CSS: цвет | Два тестовых абзаца, в том числе вложенный, получают вычисленный цвет `rgb(40, 80, 200)`. |
| CSS: медиазапрос | Есть запрос по ширине. При 360 и 600 px размер абзацев — 1rem, при 601 px сохраняется исходный тестовый размер. Изменение базового шрифта с 16 до 20 px проверяет относительную единицу. |
| Python / JavaScript: вычисления | `price = 12`, `count = 3`, произведение сохраняется в `total` и выводится. При подстановке 5 и 4 результат меняется на 20. |
| Python / JavaScript: цикл | `for` выводит переменную цикла: 1, 2, 3 на отдельных строках. После расширения границы выводится также 4; готовые строки не заменяют цикл. |
| Python / JavaScript: функция | `double` получает один параметр и возвращает число, умноженное на два. Проверяются вывод `double(5)` и значения 0, 3, -2. |
| HTML: абзацы и списки | Видимый непустой `p` и `ul` минимум с двумя видимыми непустыми дочерними `li`. |
| CSS: отступы | Все подготовленные `.card` получают padding/margin 1rem и сплошную границу 2px. Изменение базового шрифта проверяет относительные отступы. |
| CSS: Flexbox | У `.cards` включены `display: flex`, `gap: 1rem` и `flex-wrap: wrap`. Промежутки проверяются с обычным и увеличенным базовым текстом. |

В заданиях на условия принимаются сообщения из обеих локализаций: «Ура!» / “Great!” и «Можно начать» / “Ready to begin”. Смена языка не требует переводить уже написанный код. Отступы вокруг результата вывода не учитываются.

Acorn и Python `ast` разбирают структуру программы. Python выполняет пробные запуски в одном изолированном Worker; JavaScript — в отдельном Worker для каждого запуска. CSS измеряется браузером в служебных рамках: `allow-same-origin` разрешает родителю читать размеры, а отсутствие `allow-scripts` запрещает скрипты. HTML предварительно очищается, CSP блокирует внешние ресурсы. Пользовательские стили не применяются к платформе.

Это учебная проверка начальных конструкций, а не доказательство правильности произвольной программы. В частности, сложные способы создания переменной внутри функции или вывода через собственные обёртки могут не соответствовать критериям урока. Локальный результат не служит защищённым экзаменационным баллом.

Подробные результаты текущей попытки не сохраняются после выхода из шага. Сохраняются черновик и факт прохождения урока. Если после успеха изменить код, прошлое достижение остаётся, а новый вариант нужно проверить заново. Отметки прохождения с предыдущих этапов сохраняются. После расширения с трёх до шести уроков пройденные первые три остаются отмечены: например, прогресс 3 из 3 становится 3 из 6. Новые уроки добавлены в конец, старые ключи и версия локального хранилища сохранены.

## Как устроен запуск

1. Python 3.14 работает через Pyodide 314.0.7, JavaScript — в модульном Web Worker. Worker создаётся из data URL в рамке `sandbox="allow-scripts"` без `allow-same-origin`.
2. Рамка и процесс выполнения имеют непрозрачный origin. Ученический код не исполняется в React-странице и не получает её DOM, cookies или localStorage. Передача сообщений проверяет источник рамки.
3. Content Security Policy запрещает сетевые запросы JavaScript. Для Python разрешены только локальные файлы интерпретатора в `runtime/python/`; JS-мост Pyodide получает пустой объект. Установка сторонних пакетов и `input()` в этой версии не поддерживаются. Файлы Python находятся в виртуальной файловой системе, а не на диске пользователя.
4. Каждый запуск создаёт новый Worker. Завершение, кнопка «Остановить», выход из практики и смена урока уничтожают его. Защитный предел выполнения — 5 секунд после загрузки среды; это не таймер прохождения задания. Число попыток и время редактирования не ограничены.
5. Вывод ограничен 100 сообщениями / 12 000 символами. Подготовка среды ограничена 45 секундами. Это защита интерфейса от зависания и переполнения вывода, не полноценная системная квота памяти: намеренное исчерпание памяти браузера не исключается.
6. HTML очищается DOMPurify и показывается в отдельной рамке с пустым sandbox и CSP. Скрипты, ссылки, формы, внешние изображения и сетевые стили исключены. Браузер может исправлять HTML и пропускать неверные CSS-правила, поэтому предпросмотр не заменяет проверку задания.
7. Для синтаксических ошибок JavaScript Acorn определяет строку без выполнения кода в основной странице. Для Python используется информация об ошибке интерпретатора. Цветовая отметка дублируется текстом и кнопкой перехода к строке.

Pyodide загружается только при первом запуске Python. Его локальные файлы занимают примерно 14 МБ до сжатия. Vite копирует их из установленного пакета при запуске и сборке; сторонний CDN во время работы сайта не используется. На будущем хостинге для `runtime/python/` нужен заголовок `Access-Control-Allow-Origin: *`; локальный сервер Vite уже задаёт его только для этой папки. Это нужно проверить при публикации.

JavaScript-среда предназначена для консольных программ: `document`, `prompt`, сетевые запросы и импорт внешних библиотек недоступны. Незавершённые таймеры отменяются, когда основной код заканчивается. Чтение с NVDA, JAWS, VoiceOver и TalkBack нужно дополнительно проверить вручную; редактор использует обычный `textarea`, чтобы сохранять стандартные команды ввода и чтения.

## Структура и простое объяснение кода

- `src/App.jsx` — компоненты интерфейса. `useState` хранит выбранные настройки, `useLayoutEffect` применяет язык и тему к странице.
- `src/content.js` — словари RU/EN и планы трёх направлений. Здесь меняются тексты.
- `src/styles.css` — цвета, стеклянные поверхности, адаптивность и состояния кнопок. CSS-переменные позволяют менять тему в одном месте.
- `src/AccessibilityDialog.jsx` — панель настроек на нативном HTML-элементе `dialog`. Браузер сам удерживает фокус в открытой панели.
- `src/preferences.js` — допустимые значения, чтение, применение и сохранение настроек. Повреждённые данные игнорируются.
- `src/lessons.js`, `src/additionalLessons.js` — содержание 18 уроков в двух языках: теория, примеры, задачи и подсказки.
- `shared/curriculum.js` — порядок и режим редактора каждого урока; каталог используется также при проверке прогресса в браузере и API.
- `src/LessonWorkspace.jsx` — экран урока: выбор направления, шаги, практика и сохранение успешного прохождения.
- `src/learningState.js` — локальное сохранение урока, черновиков и прогресса с проверкой загруженных данных.
- `src/CodeEditor.jsx` — доступное поле кода, запуск/остановка, результат, ошибки и HTML/CSS-предпросмотр.
- `src/editorText.js` — подписи и доброжелательные подсказки ошибок RU/EN.
- `src/AssignmentCheck.jsx` — кнопки проверки и отмены, критерии результата и последовательные подсказки.
- `src/assessment/assessmentText.js` — тексты проверки и подсказки RU/EN.
- `src/assessment/checkAssignment.js` — проверка структуры JavaScript и организация изолированных запусков.
- `src/assessment/python-assessment.py` — проверка структуры Python и пробные запуски с разными значениями.
- `src/assessment/checkWeb.js` — измерение заголовка, цвета и размеров текста в отдельных рамках.
- `src/account/AccountDialog.jsx` — доступные формы аккаунта, код восстановления и выбор версий черновиков.
- `src/account/useLearningSync.js` — отдельные гостевые и личные копии, отправка изменений и обработка конфликтов.
- `src/account/api.js`, `accountText.js` — запросы API и сообщения RU/EN.
- `shared/progress.js` — общие правила проверки и объединения прогресса.
- `server/` — Express API, вход, сессии и PostgreSQL-хранилище; подробности в его README.
- `scripts/dev.mjs` — запуск сайта и API одной командой.
- `src/runtime/execute.js`, `sandbox-bridge.js`, `javascript-worker.js`, `python-worker.js` — изоляция и выполнение программ.
- `src/runtime/preview.js` — очистка HTML и подготовка предпросмотра.
- `scripts/python-runtime.mjs` — копирование файлов Pyodide для локального размещения.
- `public/licenses/` — лицензии Acorn, DOMPurify, Pyodide и Python.
- `src/assets/OpenDyslexic-Regular.woff2` — шрифт, который загружается локально. Текст лицензии — `public/fonts/OFL.txt`.
- `src/main.jsx` — подключение React к HTML.
- `index.html` — документ страницы и раннее применение сохранённой темы.
- `vite.config.js` — сборка с относительными ссылками для будущего GitHub Pages.
- `tests/accessibility.spec.js` — проверки доступности и поведения в браузере.

Семантика HTML решает основную работу: `header`, `nav`, `main`, `section`, `footer`, настоящие кнопки, ссылки, `select`, `details` и `summary`. ARIA добавляет названия областям, состояние переключателя примера и объявление изменения примера. Декоративные SVG скрыты от скринридера.

## Проверка сборки и тесты

```powershell
pnpm build
pnpm test:api
pnpm exec playwright install chromium
pnpm test:a11y
```

В текущем окружении доступен Chrome, поэтому можно использовать его без загрузки Chromium:

```powershell
node node_modules/vite/bin/vite.js build
$env:PLAYWRIGHT_CHANNEL = 'chrome'
node node_modules/@playwright/test/cli.js test
```

Тесты проверяют axe WCAG A/AA в обеих локализациях и темах, в том числе панель, высокий контраст и шаги урока; клавиатуру, локальное хранение, системную тему, уменьшение движения, ширины 320–1440 px и увеличение текста. Отдельные сценарии проходят уроки всех трёх направлений на RU/EN и проверяют сохранение прогресса. `tests/editor.spec.js` проверяет настоящий Python/JavaScript, ошибки и их строки, блокировку сети/хранилища, остановку бесконечного цикла, предел вывода, сбой загрузки Python и очистку HTML. `tests/assessment.spec.js` проходит все 18 заданий на обоих языках и проверяет альтернативные решения, неверные заготовки, границы условий, вычисления, циклы, возвращаемые значения функций, семантику списков, относительные отступы, Flexbox, отмену, фокус подсказок и мобильные результаты. Снимки сохраняются в `test-results/`. API дополнительно проверяет сохранение всех 18 черновиков и совместимость старого прогресса.

## Что проверить вручную

1. Нажать Tab сразу после загрузки: появляется «Перейти к содержимому». Enter переносит фокус к основному содержимому.
2. Пройти элементы Tab и Shift+Tab. Фокус виден; кнопки работают через Enter/Space; селектор темы — стрелками. Ловушек фокуса нет.
3. Переключить язык и тему; обновить страницу. Настройки сохраняются, заголовки и подписи переведены.
4. Включить системное уменьшение движения. Кнопки больше не смещаются при наведении/нажатии.
5. Проверить 200% масштаб и 400% при исходной ширине 1280 px: содержимое остаётся доступным без горизонтальной прокрутки.
6. Проверить текстовые интервалы: межстрочный 1.5, межабзацный 2, межбуквенный 0.12 и межсловный 0.16 от размера шрифта; ничего не обрезается.
7. NVDA/Chrome, JAWS/Edge, VoiceOver/Safari и TalkBack/Chrome: проверить заголовки, области, названия кнопок, состояние примера и раскрытие планов.
8. На настоящем сенсорном устройстве проверить управление без hover и ориентации экрана.
9. Открыть «Настройки»: проверить каждую опцию по отдельности, затем несколько одновременно. Обновить страницу и проверить сохранение; нажать «Сбросить настройки».
10. На ширине 320 px и при размере текста 150% прокрутить всё окно панели до кнопок «Сбросить настройки» и «Готово». Поля и кнопки должны оставаться доступны, в том числе при малой высоте окна.
11. Открыть панель клавишей Enter, пройти её Tab/Shift+Tab, закрыть Esc. Фокус должен вернуться на кнопку «Настройки».
12. В карточке направления нажать «Начать урок». Пройти четыре шага. На «Практике» вписать свой ответ, затем открыть образец на «Проверке».
13. Ввести верное решение на практике, открыть «Проверку» и нажать «Проверить решение». Урок должен отмечаться пройденным автоматически. Перейти к следующему и обновить страницу: номер урока, прогресс и черновик предыдущего урока должны сохраниться.
14. Переключить язык во время урока: содержание и подписи меняются, прогресс остаётся. Проверить шаги клавиатурой и скринридером.
15. В Python запустить `print("Привет!")`; затем `if True` без двоеточия. Сообщение об ошибке должно объяснить проблему и предложить переход к строке.
16. В JavaScript запустить `console.log(2 + 3)`, затем `while (true) {}`. Кнопка остановки должна работать, а код — сохраняться.
17. В HTML запустить `<h1>Моя страница</h1>`, в уроке CSS — `p { color: #2850c8; }`. Предпросмотр должен отобразить изменения.
18. Убедиться, что Tab выходит из текстового поля, Ctrl/⌘+Enter запускает программу, ошибка обозначена не только цветом, а результат доступен для чтения и копирования.
19. Проверить пустой ответ и `print("")`: урок не должен отмечаться пройденным. Раскрыть три подсказки с клавиатуры; фокус остаётся на кнопке, новые подсказки доступны скринридеру.
20. В уроке Python с условием заменить `>=` на `>`: критерий для points = 5 должен подсказать включить границу. Ошибка не должна обнулять уже сохранённые достижения.
21. В третьем уроке CSS попробовать безусловное `p { font-size: 1rem; }`: проверка ширины 601 px должна указать на необходимость медиазапроса. `16px` внутри правильного запроса не должно проходить критерий относительного размера.
22. Начать проверку бесконечного цикла и нажать «Остановить проверку»; затем повторить с переходом к практике. Код сохраняется, скрытая проверка не продолжает работать.
23. Открыть «Аккаунт» с клавиатуры, зарегистрировать тестовый аккаунт и сохранить код восстановления. Esc закрывает окно и возвращает фокус кнопке аккаунта. Пароль можно вставить и показать.
24. Войти в этот аккаунт в другом браузере: сохранённый ответ и пройденные уроки должны появиться. После выхода должен восстановиться отдельный гостевой прогресс.
25. Изменить один черновик на двух устройствах во время потери связи. После восстановления связи должны появиться обе версии и выбор пользователя.

Автоматические тесты не подтверждают полное соответствие WCAG 2.2 AA. Совместимость со всеми четырьмя скринридерами требует ручной проверки на соответствующих устройствах. На этой стадии мы закладываем основу доступности, а не заявляем сертификацию.

## Архитектура следующих этапов

Фронтенд: React + Vite. Бэкенд: Node.js/Express API и PostgreSQL; локально используется PGlite. GitHub остаётся местом для исходников. GitHub Pages не запускает Node.js API; при публикации предпочтителен единый HTTPS-адрес сайта и API. Конкретный внешний хостинг пока не подключён.

Обучение и локальное сохранение доступны без регистрации. Необязательный аккаунт синхронизирует прогресс между устройствами. Пользовательский код выполняется в изолированной браузерной среде; API прогресса хранит черновики и не исполняет их.

Публикация и настройка серверов относятся к последующим этапам. Сейчас внешние сервисы и платные ресурсы не создаются.
